# VESTI MCP + Skill 配套历史文件定位方法

## 完整技术审计与迭代记录

更新时间：2026-08-17

> 面向产品介绍或项目汇报，请先阅读[实验成果摘要](PUBLIC-RESULTS-ZH.md)。本文保留全部实验、版本诊断和统计边界，用于技术评审与复现。

## 结论摘要

VESTI 的历史文件定位能力是一套配套方法，不是两个彼此独立的产品。它先通过 MCP 从历史会话中检索文件、项目和支撑会话，再由 Skill 组织检索、核对完整查询锚点、收敛到最小文件集合，并在证据不足时拒答。

本文统一使用“VESTI 配套方法”指代二者共同工作的完整链路。为了判断问题出在召回还是 Agent 决策，实验中保留了内部消融组；这些消融只用于工程归因，不代表 MCP 与 Skill 是两个独立方案。

当前验证结果集中在四项能力：

1. 确定性检索层在 66 个计分任务中达到 **66/66（100.0%）**，旧检索链为 **54/66（81.8%）**，提高 **18.2 个百分点**；概念簇 Bootstrap 95% CI 为 **[+17.4,+19.0]**，中位工具调用由 11 次降至 1 次。
2. 文件名定位专项达到 **12/12（100%）**，旧流程为 **4/12（33.3%）**，提高 **66.7 个百分点**，McNemar `p=0.0078`。
3. 修订后的 V3 在 24 个首次运行前冻结的新回归任务中达到 **23/24（95.8%）**；18 个正例全部精确通过，项目、证据会话和历史标记均正确，没有额外文件。
4. 在 16 个事前冻结的 Skill 功能合同对齐任务中，完整方法达到 **14/16（87.5%）**，相同 MCP 的无 Skill 组为 **12/16（75.0%）**；配对为 **2 胜、0 负、14 平**。正例由 11/12 提高到 12/12，困难负例中的错误文件由 3/4 降至 2/4。

早期 72 题端到端实验也呈现正向信号：完整方法为 **93.1%**，旧流程为 **84.7%**，观察差为 **+8.3 个百分点**。总体置信区间包含 0，因此该数字用于描述工程趋势，不作为总体显著性结论。

本文后半部分完整保留了 V2 压力测试及其暴露的候选过度合并问题。该结果促成了 V3 的“完整锚点 + 支撑会话求交”改造；新回归集中没有再次出现这一症状。不同实验对应不同版本与数据集，不能合并计算一个综合提升率。

文中 pp 表示百分点，CI 表示置信区间；常规负例是完全没有相关证据的任务，困难负例是存在相似干扰、但不存在完整目标证据的任务；ITT 表示运行失败仍按错误计入。

## 方法定义

完整链路如下：

```text
用户问题
  → Skill 识别文件名、项目范围、稀有标识和多文件意图
  → MCP 从历史会话检索文件候选及支撑会话
  → Skill 在 session 级核对完整锚点，求取最小证据集合
  → 证据完整：返回文件、项目和会话来源
  → 证据不足：拒答，不把宽主题或数字碎片当成命中
```

两个环节在产品架构中串成同一条链路：检索执行层负责找到历史证据，Agent 控制层负责判断这些证据能否支持最终答案。确定性实验验证前一环节，Agent 实验验证完整链路，两类结果不能合并成一个统计量。产品会将二者作为一套方法共同交付，但现有消融尚未证明控制层在所有任务上都有独立增益。

## 实验一：五题最小链路验证

最初使用 5 个合成任务验证了完整测量链路，包括语义文件、文件名反查、跨项目、多日历史路径和负例。其中 4 个正例进入 Hit/Recall 指标，另有 1 个负例单独评分。

- 旧检索链 Hit@3：75%；新文件定位链 Hit@3：100%。
- 平均可见工具调用：2.6 次降至 1.0 次。
- 两组在常规负例上均未返回文件。

这轮实验只证明 SQLite/FTS、MCP、评分器和结果记录可以跑通，不承担产品效果结论。

原始产物：[pilot-report.md](results/pilot-report.md)

## 实验二：早期 trigram 大基准

随后在 72 个配对任务上测试早期实现，其中 66 题进入主终点，6 个困难负例单列。旧链成功率为 51.5%，新链为 57.6%，差值 +6.1pp，概念簇 95% CI 为 [-8.7,+17.9]。该阶段未得到稳定的总体提升，并暴露了中文查询、项目过滤、候选截断和多文件排序问题。

这轮结果的价值在于发现问题，不应作为最终效果数字。

## 实验四：早期 72 题端到端四臂实验与事后完整方法比较

这轮使用 `gpt-5.6-luna`，每题启动独立 Agent，共完成 72×4=288 次运行。实验内部使用“旧/新工具面 × 无/有 Skill”四臂设计来定位贡献；对外的完整方法比较是“新检索链 + Skill”对“旧检索流程”。

| 范围 | 旧流程 | 完整配套方法 | 差值 | 95% 概念簇 CI |
| --- | ---: | ---: | ---: | ---: |
| 全部任务 | 61/72，84.7% | 67/72，93.1% | +8.3pp | [-1.4,+15.3] |
| 全部正例 | 52/60，86.7% | 58/60，96.7% | +10.0pp | [+1.7,+16.7] |
| 文件名定位 | 4/12，33.3% | 12/12，100.0% | +66.7pp | [+41.7,+91.7] |
| 全部负例 | 9/12，75.0% | 9/12，75.0% | 0pp | [-25.0,+25.0] |

完整方法相对旧流程的中位工具调用由 7 次降至 4 次，中位输入 Token 由 78,694 降至 67,069，中位端到端运行时长由 27.66 秒降至 26.87 秒。

总体 +8.3pp 的区间跨过 0，McNemar `p=0.146`，所以只能写成“观察到提升”。文件名定位子组的 McNemar `p=0.0078`，但它只有 12 题，且是事后分层。除去文件名任务后，正例从 100% 变为 95.8%，说明早期总体收益主要来自新文件名反查能力，不能解释为 Skill 与 MCP 在所有任务上都有协同增益。

原始产物：[composite-report.md](results/agent-factorial-v2-final-limit12/composite-report.md)

## 实验七：V2 预注册正式压力测试

正式集在 Skill 冻结后生成和锁定，包含 120 个任务、20 个概念簇、4 个实验臂和 3 次重复，共 1,440 次运行。最终有 1,437 次正常完成，3 次 Agent 运行失败按 ITT 计零；数据完整性和运行有效性门槛均通过，但效果主终点失败。

正式主比较测试的是同一现代 MCP 条件下，V2 Skill 的增量：

| 指标 | 仅检索层消融组 | 完整 V2 方法 | 差值 |
| --- | ---: | ---: | ---: |
| 全部任务 | 276/360，76.7% | 246/360，68.3% | -8.3pp |
| 300 个正例 | 262/300，87.3% | 187/300，62.3% | -25.0pp |
| 60 个负例正确拒答 | 14/60，23.3% | 59/60，98.3% | +75.0pp |

主效应 D−B 为 -8.33pp，95% CI [-14.44,-2.77]，预注册主终点失败。完整方法相对旧流程的描述性结果同样为负：68.3% 对 77.5%，差值 -9.2pp。因为主终点没有通过，后续层级检验不能作为确认性成功结论。

这轮实验揭示了明确的权衡：V2 控制规则大幅减少了负例误报，但候选集合收敛失败，导致正例精确匹配下降。113 个失败正例的正确文件都已经出现在第一次 MCP 候选中，但 Agent 又合并了其他支撑会话的文件；74 次找全标准答案文件后增加了额外文件，39 次既漏文件又增加额外文件，共加入 430 个非标准答案文件。因此失败发生在配套方法的候选核验环节，而不是 MCP 没有召回正确候选。

安全结果仍然有价值，但必须区分预注册合同误报和事后判断的实际错误文件：

- 预注册的困难负例 ITT 合同误报率：仅检索层消融组为 29/30（96.7%），完整方法为 0/30（0%）；前者有 20 次实际返回 `files=[]`，但错误设置了 `answerable=true`，不能全部解释为返回了错误文件；

- 困难负例真正返回错误文件：仅检索层消融组为 9/30（30%），完整方法为 0/30（0%）；
- 常规负例真正返回错误文件：仅检索层消融组为 1/30（3.3%），完整方法为 0/30（0%）；
- 中位工具调用 6→3，中位输入 Token 130,728→74,593，中位端到端运行时长 30.73s→27.96s。

这些效率变化伴随着正例准确率下降，不能写成“同等质量下提效”。正式实验的作用是发现 V2 设计缺陷，并为 V3 的会话级完整锚点核验提供依据。

## 实验八：V3 快速工程回归

V3 将候选选择改为“完整锚点 + 支撑会话求交”，不再把不同检索结果直接并集。快速回归使用 24 个此前未运行、首次模型调用前冻结的针对性新任务，其中有 18 个正例、6 个负例、12 个新概念；完整方法和仅检索层消融组各运行一次，共 48 次调用。

| 指标 | 仅检索层消融组 | 完整 V3 方法 | 变化 |
| --- | ---: | ---: | ---: |
| 精确成功率 | 23/24，95.8% | 23/24，95.8% | 0pp |
| 正例成功率 | 18/18，100% | 18/18，100% | 0pp |
| 负例正确拒答 | 5/6，83.3% | 5/6，83.3% | 0pp |
| 工具调用总数 | 182 | 146 | -19.8% |
| Input Token 总数 | 2,060,476 | 2,161,987 | +4.9% |
| 端到端运行时长总和 | 712.9s | 738.4s | +3.6% |

18 个正例全部返回完整且唯一的标准答案文件集合，项目、证据会话和历史标记均正确，没有额外文件。V2 正式实验中的候选过度并集症状没有复现，因此 V3 通过了针对该缺陷的工程回归。

两组唯一失败的是同一个连字符标识负例。查询中的完整标识并不存在，但 MCP 将其拆成单词和数字，数字碎片命中了无关会话；两组随后都错误返回了 5 个文件。下一步需要让 MCP 暴露完整短语命中、token coverage 和 matched snippet，并要求 Skill 在原始证据不含完整标识时拒答。

本轮两组准确率完全相同，所以不能据此宣称 V3 带来了准确率提升。调用总量下降主要来自负例更早停止，而 Skill 文本和正例的强核验增加了 Token 与时延，也不能宣称全面降低成本。

## 实验九：Skill 定向能力验证

这轮实验不是从普通查询中抽样，而是依据冻结 Skill 的功能合同，事前构造需要完整条件核验、项目约束、会话求交或拒答决策的定向任务。它用于检查 Skill 是否按设计工作，不用于估计真实用户查询中的总体平均提升。

实验共有 16 题、8 个独立 concept，中文和英文各 8 题。12 个正例各有一个完整支撑会话和三个部分匹配干扰会话；4 个关系型负例的条件分别或成对存在，但没有任何会话同时满足全部条件。两组使用相同的 `gpt-5.6-luna`、数据库、输出格式和四个只读 MCP 工具，仅 D 组加载冻结 Skill。全部题目、gold、评分器、调度和哈希在首次调用前锁定，32/32 次调用完成，结果中没有删题、补题或重跑。

| 指标 | 同一 MCP、无 Skill | MCP + 冻结 Skill | 变化 |
| --- | ---: | ---: | ---: |
| 严格任务成功率 | 12/16，75.0% | 14/16，87.5% | +12.5pp |
| 正例严格成功率 | 11/12，91.7% | 12/12，100.0% | +8.3pp |
| 正例零额外文件率 | 11/12，91.7% | 12/12，100.0% | +8.3pp |
| 困难负例正确拒答 | 1/4，25.0% | 2/4，50.0% | +25.0pp |
| 困难负例实际错误文件 | 3/4，75.0% | 2/4，50.0% | -25.0pp |
| 工具调用总数 | 142 | 134 | -5.6% |
| Input Token 总数 | 1,851,957 | 1,862,114 | +0.5% |
| 端到端时长总和 | 637.7s | 663.2s | +4.0% |

配对结果为 2 胜、0 负、14 平。一个增益来自多文件题：无 Skill 组把三个近似会话中的 6 个文件做了并集，Skill 组只返回完整支撑会话中的 2 个标准答案文件；另一个增益来自关系型负例：Skill 组识别出三个条件没有在同一会话中共同成立并正确拒答。其余两个英文关系型负例仍被两组误判，说明完整关系核验还不够稳定。

这项实验达到事前定义的工程门槛：D 至少 13/16、净改善至少 2 题、正例不回退、负例错误文件不增加。它仍然只是小规模、单模型、单次采样的探索性机制验证。聚类 Bootstrap 95% CI 为 [0.0,+31.3]，exact McNemar `p=0.50`，不能称为总体统计显著。工具调用略降，但 Token 总量和时长没有下降，也不能写成全面提效。

## 内部消融如何放置

对外产品叙事始终使用“VESTI 配套方法”。报告中的无 Skill、安慰剂和旧工具臂只用于回答三个工程问题：

1. 正确文件是否已经由检索层召回；
2. 错误发生在候选召回还是 Agent 核验；
3. 调用、Token 和时延变化来自工具能力还是控制规则。

消融结果应放在方法或附录中，不应拆成两个独立产品。但它们不能被删除，因为没有消融就无法证明哪一部分导致了提升或回退。

在 16 题定向实验中，仅检索层消融组必须留在正文，因为该实验的目的就是隔离同一 MCP 上的 Skill 增量。产品叙事仍使用“配套方法”，实验归因则必须保留 Skill 开 / 关对照。

## 复现边界

- 数据集均为合成、可检查语料，不是真实用户分布。
- 早期端到端实验每个任务只运行一次；V3 快速回归同样只有一次模型采样。
- 主要 Agent 实验只使用 `gpt-5.6-luna` 和 Codex CLI `0.144.6`，不能直接外推到其他模型。
- 确定性实验的 payload 是 UTF-8 字节，不是 Token；5.51ms 是进程内 MCP 诊断耗时，不是完整产品时延。
- V2 正式集已经用于诊断，不能在其上修改 V3 后再次宣称确认性成功。
- 下一次确认性实验需要使用新的冻结 Skill、新的未见语料、至少多个模型重复，并把 exact-phrase negative 作为预注册安全指标。
- 16 题定向能力实验为合成且有意富集的功能合同对齐任务，单模型、单次采样；全部任务和失败均报告，但不能估计自然用户总体增益，也不能与既有实验合并。
