# VESTI 文件定位 V3 快速工程验证

## 结论

本轮 24 个全新任务、48 次 `gpt-5.6-luna` 调用全部有效完成。B 组（相同 MCP、无 Skill）和 D 组（相同 MCP、V3 Skill）均为 23/24，精确成功率均为 95.8%，因此本轮没有观察到 Skill 带来的准确率增量。

V3 Skill 在 18/18 个正例上均返回完整 Gold 文件集合，且没有额外文件。旧版正式实验中出现的“把多个会话候选做并集、返回大量额外文件”症状，在这组专门针对该问题构造的新回归题中没有复现；但 B 组也达到 18/18，因此这只能证明 V3 通过了针对性工程回归，不能证明 Skill 导致准确率提升。

## 实验设计

- 24 个从未用于此前实验的新任务，包含 12 个新概念、44 个合成历史会话和 8 个项目。
- 类别：semantic 4、filename 4、multi-file 4、cross-project 4、stale-path 2、negative 6。
- 语言：中文 10、英文 10、中英混合 4。
- 18 个正例均含同 basename 近似干扰项；完整查询锚点只出现在 Gold supporting session。
- B/D 使用相同模型、相同输出 schema、相同四个 VESTI MCP 工具和逐次复制的相同数据库；只有 D 注入冻结的 V3 Skill。
- 每题每组运行一次，共 48 次；每次使用 fresh ephemeral Codex 进程，禁用 shell、web、apps、plugins、用户配置和仓库规则。
- 正例必须返回完整且唯一的 Gold 文件集合、零额外文件、正确项目、正确 evidence session，并设置 `historical_only=true`；负例必须 `answerable=false` 且 `files=[]`。
- 全部材料在首个模型调用前锁定，运行后未调参。

配对结果为 D 胜 0、负 0、平 24。机械计算的 cluster-bootstrap 区间为 `[0, 0]`，只是因为 24 个观察差值全部为零，不能解释成总体真实效应已被精确证明为零，也不能作为等效性证明。

工具调用减少并非所有任务稳定受益：正例调用从 84 增至 93，负例从 98 降至 53；36 次净减少中有 30 次来自一个无 Skill 组过度探索的负例。与此同时，Skill 文本和正例强制核验增加了 Token 与时延，因此不能概括成“全面提效”或“降低成本”。

## 唯一失败与根因

两组都只在 `rapid-negative-08` 失败。题目要求寻找完整标识 `velvet-ibis-26` 和 `opal-cairn-84`，但二者在语料中均不存在。MCP 查询规划在连字符处拆词并进行宽召回，数字碎片 `26` 和 `84` 命中了无关的 opaque session title。两组随后都把这些部分命中误解释为完整标识证据，并返回了相同的 5 个错误文件。

最小修复方向：

1. 对错误码、API 名和字母数字连字符标识增加完整字面串或 all-token 覆盖校验。
2. MCP 返回 matched tokens、coverage 和 matched snippet，区分完整命中与数字碎片命中。
3. Skill 明确规定：原始 evidence 不含完整标识时必须拒答，数字碎片不得构成标识命中。

## 可汇报口径

可以说：

> 在 24 个全新任务的快速工程验证中，V3 Skill 保持了与无 Skill 基线相同的 95.8% 精确成功率；18 个正例全部精确通过，旧版的候选过度并集症状未再复现；工具调用总数减少 19.8%。

必须同时披露：

- 本轮没有得到“组合准确率为正”或“Skill 显著提升准确率”的结果。
- Token 增加约 4.9%，时延增加约 3.6%，不能声称全面降低成本。
- 本轮是单模型、单次重复、合成数据、针对特定失败模式的探索性回归，不替代正式确认性实验。
- B/D 都使用新版 MCP，本轮隔离的是 Skill 的增量作用，不能用它证明 MCP+Skill 相对无 MCP 方案的整体增益。
